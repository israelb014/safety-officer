# קצין בטיחות — מערכת מעקב רכבים ונהגים (גרסה 2)

מערכת פשוטה לקצין בטיחות: תאריכי תוקף של רכבים, אוטובוסים ונהגים, יומן טכוגרף, טיפולים ומסמכים —
עם התראה יומית אחת לטלפון.

- **אתר:** `https://israelb014.github.io/safety-officer/`
- **צד לקוח:** HTML/CSS/JavaScript רגילים, בלי שלב בנייה. מתארח ב-GitHub Pages.
- **צד שרת:** Supabase (חינם) — מסד נתונים, התחברות ואחסון קבצים.
- **התראות:** GitHub Actions שולח כל בוקר הודעה אחת דרך האפליקציה החינמית ntfy.

> **אבטחה:** בקובץ `config.js` נמצאים רק כתובת הפרויקט ומפתח ה-**anon**. מותר שהם יהיו ציבוריים, כי הנתונים מוגנים ב-Row Level Security
> (רק משתמש מחובר רואה משהו). את מפתח ה-**service_role** אסור לשים בקוד. הוא נשמר רק ב-GitHub Secrets.

## התקנה — צעד אחר צעד

### 1. יצירת פרויקט Supabase
1. נכנסים ל-<https://supabase.com> ← **Start your project** ← מתחברים (אפשר עם GitHub).
2. **New project** ← שם: `safety-officer` ← בוחרים סיסמה למסד הנתונים (שומרים אותה במקום בטוח) ← Region: **Central EU (Frankfurt)** ← **Create new project**.
3. מחכים כ-2 דקות עד שהפרויקט מוכן.

### 2. הרצת `schema.sql`
1. בתפריט הצד: **SQL Editor** ← **New query**.
2. מעתיקים את כל התוכן של הקובץ [`supabase/schema.sql`](supabase/schema.sql) ומדביקים.
3. לוחצים **Run**. צריך להופיע `Success. No rows returned`.
   הסקריפט יוצר את כל הטבלאות, את הרשאות האבטחה (RLS), את תיקיית הקבצים הפרטית `documents` ואת שורת ההגדרות.
   מותר להריץ אותו שוב, הוא לא מוחק נתונים.

### 3. חסימת הרשמה של משתמשים חדשים
1. **Authentication** ← **Sign In / Providers** (בגרסאות ישנות: **Providers**) ← **Email**.
2. מכבים את **Allow new users to sign up** ← **Save**.
   (משאירים את **Email** עצמו דלוק.)

### 4. יצירת המשתמש של ניסים
1. **Authentication** ← **Users** ← **Add user** ← **Create new user**.
2. מזינים אימייל וסיסמה (לפחות 8 תווים) ← מסמנים **Auto Confirm User** ← **Create user**.
3. את האימייל והסיסמה מוסרים לניסים. אפשר לשנות את הסיסמה אחר כך מתוך המערכת (הגדרות ← שינוי סיסמה).

### 5. העתקת הכתובת ומפתח ה-anon ל-`config.js`
1. **Project Settings** (גלגל השיניים) ← **API** (או **Data API** / **API Keys**).
2. מעתיקים את **Project URL** (למשל `https://abcd1234.supabase.co`).
3. מעתיקים את המפתח **anon public**. **לא** את `service_role`!
4. ב-GitHub פותחים את הקובץ `config.js` ← עיפרון (Edit) ← מחליפים את שני הערכים ← **Commit changes**:
   ```js
   export const SUPABASE_URL = 'https://abcd1234.supabase.co';
   export const SUPABASE_ANON_KEY = 'eyJhbGciOi...';
   ```

### 6. הוספת 2 סודות ל-GitHub Actions
ב-GitHub: **Settings** ← **Secrets and variables** ← **Actions** ← **New repository secret**:

| Name | Value |
|---|---|
| `SUPABASE_URL` | אותה כתובת מסעיף 5 |
| `SUPABASE_SERVICE_KEY` | Supabase ← Project Settings ← API ← **service_role** (סודי!) |

אופציונלי: `NTFY_TOPIC`. לא צריך אותו, כי המערכת יוצרת את שם הערוץ לבד בכניסה הראשונה ושומרת אותו במסד הנתונים.
הסוד משמש רק כגיבוי אם הערוץ במסד הנתונים ריק.

### 7. הפעלת GitHub Pages
1. ב-GitHub: **Settings** ← **Pages**.
2. **Source:** `Deploy from a branch` ← **Branch:** `main` ← תיקייה: `/ (root)` ← **Save**.
3. אחרי דקה-שתיים האתר זמין ב-`https://israelb014.github.io/safety-officer/`.

### 8. הרצה ידנית ראשונה של ההתראות
1. נכנסים פעם אחת לאתר ומתחברים (כך נוצר שם ערוץ ההתראות).
2. ב-GitHub: **Actions** ← **Daily alerts** ← **Run workflow** ← **Run workflow**.
3. אחרי כחצי דקה ההרצה צריכה להיות ירוקה. אם יש פריטים לטיפול, תגיע הודעה לטלפון.
   מעכשיו זה רץ אוטומטית כל יום ב-05:00 UTC (‏08:00 בשעון קיץ, ‏07:00 בשעון חורף).
   ההרצה היומית גם שומרת על פרויקט Supabase החינמי פעיל (פרויקט שלא נגעו בו שבוע נכנס להשהיה).

### 9. התראות באייפון של ניסים (ntfy)
1. App Store ← מחפשים **ntfy** ← מתקינים (חינם).
2. באתר: **הגדרות** ← **התראות לטלפון**: מופיעים שם הערוץ וברקוד.
3. באפליקציית ntfy לוחצים **+** ← מדביקים את שם הערוץ (או לוחצים באתר "הצטרפות להתראות" / סורקים את הברקוד) ← **Subscribe**.
4. כשהטלפון שואל — **Allow** (אפשר התראות).
5. באתר לוחצים **שלח התראת בדיקה**. אמורה להגיע הודעה תוך שניות.

### 10. התקנת האתר כאפליקציה באייפון
Safari ← פותחים את כתובת האתר ← כפתור **שיתוף** (ריבוע עם חץ למעלה) ← **הוסף למסך הבית** ← **הוסף**.
ניסים נשאר מחובר גם אחרי סגירה של האפליקציה.

### 11. גיבוי
- **גיבוי אוטומטי:** בתוכנית החינמית אין גיבוי יומי שאפשר לשחזר ממנו בעצמכם, לכן מומלץ לייצא ידנית פעם בחודש.
  (בתוכנית Pro: **Database** ← **Backups**.)
- **ייצוא CSV:** **Table Editor** ← בוחרים טבלה ← **Export** (או `...`) ← **Export to CSV**. חוזרים על זה לכל טבלה.
- **ייצוא קבצים:** **Storage** ← `documents` ← בוחרים קבצים ← **Download**.

## ייבוא מהמערכת הישנה
1. ב-phpMyAdmin של המערכת הישנה: בוחרים טבלה (`vehicles`, `drivers`, `insurance`, `vehicle_test`) ← **Export** ←
   Format: **CSV** ← מסמנים **Put columns names in the first row** ← **Go**.
2. באתר: **הגדרות** ← **ייבוא מהמערכת הישנה** (הדף `import.html`, פתוח רק למשתמש מחובר).
3. מעלים את הקבצים. המערכת מנחשת לבד איזו עמודה היא מה. ב"התאמת עמודות" אפשר לתקן. בודקים את התצוגה המקדימה ← **ייבוא**.
4. מייבאים את `vehicles` יחד עם `insurance` ו-`vehicle_test` (או קודם את `vehicles`), כי הביטוחים והטסטים מקושרים לרכב לפי המזהה הישן או לפי מספר הרישוי.
5. אפשר לייבא שוב בלי ליצור כפילויות: רכבים מתעדכנים לפי מספר רישוי, ונהגים לפי מזהה ישן, ת"ז או שם.
6. קבצי מסמכים ישנים מעלים מחדש ידנית דרך מסך הרכב או הנהג.

## איך זה עובד

| מסך | מה יש בו |
|---|---|
| **בית** | ספירה: פג תוקף / עומד לפוג / תקין. כרטיס לכל פריט שפג או יפוג תוך 30 יום, עם כפתור "עדכון" שקופץ בדיוק לשדה. גם אוטובוסים עם ימי טכוגרף שלא סומנו החודש, ורכבים שהטיפול הבא שלהם קרוב (14 יום או 1,000 ק"מ). |
| **רכבים** | פרטי רכב (כולל "טיפול הבא בק"מ"), 9 תאריכי תוקף (רישיון רכב, ביטוח חובה, ביטוח מקיף, מטף, בדיקת חורף, בדיקת בלמים, מערכת שכחת ילדים, אישור תלת חודשי, אישור הדרכה קיץ/חורף), ולאוטובוס עוד 6 בדיקות ויומן טכוגרף. |
| **יומן טכוגרף** | גיליון חודשי: נבדק (X), נהג, הערה. חתימה באצבע נועלת את החודש. הדפסה ב-A4 לרוחב. |
| **נהגים** | פרטים, 2 תאריכי תוקף (רישיון נהיגה, אישור משטרה), תקנה 84 (יש/אין). אישור ההדרכה נמצא ברכב. |
| **טיפולים** | היסטוריה לפי רכב, עלות שנתית, טיפול הבא. ק"מ גבוה יותר מעדכן את הק"מ של הרכב, ו"ק"מ לטיפול הבא" מעדכן את "טיפול הבא בק"מ" של הרכב. |
| **מסמכים** | כל המסמכים, עם חיפוש וסינון. מסמך חדש לא מוחק את הקודם, הקודם עובר ל"היסטוריה". |
| **הגדרות** | התראות (ntfy + ברקוד), מתי להתריע, נפח אחסון, התקנה לאייפון, שינוי סיסמה. |

**צבעים:** ירוק = בתוקף (יותר מ-30 יום) · כתום = עומד לפוג (30 יום או פחות) · אדום = פג · אפור = לא הוזן תאריך.

**התראות:** הודעה אחת בכל בוקר. פריט נכלל 30, 14, 7 ו-1 ימים לפני התפוגה, ביום עצמו, ובכל יום אחרי שפג עד שמעדכנים.
את המועדים אפשר לשנות בהגדרות. אם אין שום דבר לטיפול — לא נשלחת הודעה. אותה הודעה לא נשלחת פעמיים באותו יום.

**מסמכים:** תמונות נדחסות בטלפון לפני ההעלאה (עד 2000 פיקסלים, JPEG). עד 10MB לקובץ. כמה תמונות בהעלאה אחת נשמרות כמסמך אחד עם עמודים.
הקבצים פרטיים ונפתחים רק דרך קישור זמני (60 שניות). גרסאות קודמות נמחקות אוטומטית שנתיים אחרי שהוחלפו. מסמך נוכחי לא נמחק אף פעם אוטומטית.

**מחיקה:** רכב או נהג עם היסטוריה (טיפולים, מסמכים, יומן) לא נמחקים אלא מסומנים "לא פעיל".

### הוספת סוג תאריך תוקף חדש
מוסיפים שורה אחת לרשימה המתאימה בקובץ [`js/items.js`](js/items.js) (`VEHICLE_ITEMS`, `BUS_ITEMS` או `DRIVER_ITEMS`).
האתר וההתראות היומיות קוראים את אותו קובץ.

## החלטות שלא הוגדרו במפורט (נבחרה האפשרות הפשוטה)
- לא הייתה תיקיית `/legacy`, ולכן העיצוב בנוי על הצבעים והגופן שהוגדרו (‎#1a3a5c, Heebo, פינות 12px).
- אוטובוס שהפך לסוג רכב אחר: תאריכי הבדיקות של האוטובוס נשמרים, אבל לא נספרים ולא מתריעים.
- "יום התפוגה" (0 ימים) נחשב דחוף, וההודעה נשלחת בעדיפות גבוהה.
- ההתראה היומית על טכוגרף בודקת רק את אתמול. במסך הבית מוצגים כל הימים מתחילת החודש שלא סומנו.
- רכב לא פעיל ונהג לא פעיל לא מופיעים במסך הבית ולא בהתראות.
- תאריך טיפול לא יכול להיות בעתיד. ק"מ לטיפול הבא חייב להיות גדול מהק"מ של הטיפול.
- "טיפול הבא בק"מ" נשמר ברכב עצמו. אם הוא ריק, נלקח הק"מ מהטיפול האחרון. תאריך הטיפול הבא נלקח מהטיפול האחרון.
- אישורי ההדרכה קיץ/חורף של נהגים הוחלפו באישור אחד לכל רכב. שורות ישנות שנשארו במסד הנתונים לא מוצגות ולא מתריעות.
- "בדיקת בלמים" מסומנת "כל 6 חודשים" בטופס כתזכורת בלבד. התאריך הבא לא מחושב אוטומטית.
- חתימת היומן נשמרת כקובץ PNG בתיקייה הפרטית (`tachograph/<vehicle>/signature/`).
- מסמכים של רכב/נהג/טיפול שנמחקו לגמרי נמחקים יחד איתם (כולל הקבצים).
- תגיות ההודעה (Tags) ב-ntfy הן `rotating_light` לדחוף ו-`warning` לרגיל.
